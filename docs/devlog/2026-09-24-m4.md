## Rulings (decisions made on the owner's behalf)
1. **M4 runs now, before the rest of M3**, in parallel with M2's round 2 (owner #25). *Cost if wrong:*
   universes and the Physics Lab's companions arrive later.
2. **The host's phone runs the world; Nakama only relays** (the spike's design, §7.3): no dedicated game
   server to pay for or run. *Cost if wrong:* the session ends when the host leaves (the world is saved on
   the host); the host's upload carries the guests, which world sync by edits (§17.0) keeps small.
3. **Self-hosted Nakama on a small VPS** (a hosting kit with automatic TLS and backups, `server/deploy/`),
   not a managed service. *Cost if wrong:* the owner runs a server (about the price of a small VPS a
   month); a managed Nakama plan can replace it without code changes (only the address and keys).
4. **Consent before under-13 social features stays** (§17.2): until the owner registers the app with a
   verification provider, release builds keep under-13 players to solo, LAN and bot friends; developer
   builds use a fake provider so every flow is tested. *Cost if wrong:* younger children can't play online
   with friends until the owner finishes that registration (a legal requirement, COPPA / GDPR-K).
5. **World sync by edits** (guests generate terrain from the seed) replaces streaming every block: the spike
   measured 4–9 Mbit/s per flying guest through the relay. *Cost if wrong:* none known; the generator is
   already deterministic (the LAN checksum test compares worlds).
