  build's but the delivered `index.mobile.pck` was 46,513,692 bytes, the old one. A returning page is controlled by the

  cached it serves its old page. So every update gave a mix (new page, old pack; with an engine update the mix could
  break the game) or the old game until the next visit. Fix (`57d19d3`): the page and its worker carry one build id

  returning page asks the browser for a newer worker (3 s at most; offline none), waits for it to take over ("Updating

  `…2633` (page, worker and delivered pack all `…2633`, 49,777,560 bytes), and the live server after the 03:51 deploy
  (the same). The one visit that moves an old worker to this mechanism can still be old; from then on updates arrive on
  the first visit.
