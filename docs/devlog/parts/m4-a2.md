## Patterns (godot-prompter skills)
- **multithreading**: chose `WorkerThreadPool.add_task` per chunk (short jobs, at most 2 at once so
  Voxel Tools' own threads keep the cores), polled with `is_task_completed` and always finished with
  `wait_for_task_completion` (every task waited for; `WorldSync._exit_tree` waits for running ones,
  because a job reads the terrain). Worker threads write only their job's fields; results are applied
  on the main thread. Rejected a long-lived `Thread` with a `Semaphore` queue (one more thread to
  start and stop per world, and ordering by nearest chunk stays simpler on the main thread).
- **multiplayer-sync**: chose snapshot interpolation with a render delay (a ring of timestamped syncs,
  shown one interval + 50 ms behind), fed by the synchronizer's `synchronized` / `delta_synchronized`
  signals, which fire only on the games that receive a sync; the body is put back where it is shown
  right in that signal, so a sync never shows as a jump. Rejected the skill's prev/current lerp by
  `Engine.get_physics_interpolation_fraction()` (it blends over one physics tick, not over a 50–100 ms
  sync interval), per-entity display nodes (every entity file would change, in code other agents own),
  and extrapolation (children's worlds: a body guessed through a wall looks worse than a short wait).

## Rulings (decided on the owner's behalf; cost if wrong)
1. **The copy of the host's blocks runs on the worker thread too**, not only the generation (the copy
   waited up to 200 ms for Voxel Tools' locks on the main thread). Voxel Tools locks its data for its
   own threads. *Cost if wrong:* a crash or a wrong list; the tests compare the worker's result with
   the main-thread diff, and the rejoin and saved-world tests compare whole worlds.
2. **At most 2 comparisons at once, and a frame asks about at most 8 lists that are not ready.**
   *Cost if wrong:* a host with a big saved world sends a new guest its saved builds a little later.
3. **The host remembers every chunk that came into each guest's view** (one flag each; over 16,384 the
   unloaded ones are forgotten), kept while the guest is away, dropped when it leaves for good.
   *Cost if wrong:* memory, well under 1 MB a guest; and the forgetting looks up to 16,384 chunks in
   one frame when the list is full (about once per 2 km a guest flies), a small hitch on the host.
4. **A rejoin waits for the old world's voxel queue to drain (at most 1.5 s) before the scene reloads**,
   and tries only after that. *Cost if wrong:* the rejoin starts 0.15–0.3 s later.
5. **The guest's goodbye stops its world streaming at once**: the world vanishes behind the goodbye
   words, and the menu comes 3 s later instead of up to 13 s. *Cost if wrong:* children see an empty sky
   behind the goodbye words for 3 s.
6. **`Game.quit_to_menu` (the host's Save & Quit, the menu from the pause menu) is not changed**: there
   the sandbox still runs, and freeing its player's viewers early would break the player. The recipe is
   in DEVELOPMENT.md §8. *Cost if wrong:* quitting while the world still streams (right after starting,
   or while flying) can freeze the game for seconds before the menu.
7. **Remote bodies are shown one sync interval + 50 ms behind their newest sync: 100 ms for players,
   150 ms for creatures.** *Cost if wrong:* creatures show 50 ms later than players; a monster's bite
   can look a moment early.
8. **The host sees its guests' players smoothed too**, and its checks (reach, hits, where it streams for
   the guest) read that place, up to 100 ms (about 0.4 m walking) behind. *Cost if wrong:* an edit at the
   very edge of reach while running could be refused.
9. **Only the vertical turn is smoothed**; tilts sync as they come. No guessing ahead: a late sync holds
   the body, then it catches up. *Cost if wrong:* a fish's or the Golem's tilt steps; under jitter over
   50 ms an occasional catch-up step (0.15–0.27 m measured, 1.4 m once right after a rejoin at load 31).
10. **Join time: the spawn stays as it was** (the experiments above were no better or worse). *Cost if
    wrong:* joins stay ~1.7–2.0 s on this loaded PC (target < 2 s on the emulator). Ideas for later, not
    mine to build: reuse the menu's signed-in session for the join (~0.5 s), put the seed in the invite so
    the guest's world starts while it signs in, and a faster generator (the real limit).
