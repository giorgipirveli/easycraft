# M6 "iPhone" Implementation Plan — the iOS build on the owner's Mac

> **For agentic workers:** this plan runs on the owner's Mac. Read `docs/IOS-START-HERE.md` first (setup), then
> CLAUDE.md and `docs/DEVELOPMENT.md`. Each task is test-first where code changes (GUT for pure rules and glue that runs
> headless), and every platform piece is verified on a real iPhone.

**Goal:** EasyCraft 1.0.x on iPhone (and iPad), playing together with Android players on the same server, in TestFlight
and then on the App Store.

**Spec:** §19 (this milestone), §7 (performance bar), §5.14 and §17 (child safety), §18 (the shop), §15.4 (store work).

**State at the start (2026-09-27):** Android release 1.0.1 (code 11) done and accepted: suite 6016/6018, every smoke run
passing, live server module 0.2.11. main = the commit this plan arrived in.

## Global constraints
- English only (owner #52). No translations, no language picker, no translated store texts.
- Only CC0 assets (credited in `assets/CREDITS.md`). No bundled fonts (the chat's Georgian letters come from the device).
- Bundle id `com.giorgi.easycraft` (the same id as on Google Play). Version and build number follow the Android
  version (`test_release_version.gd` keeps every preset in step).
- The owner's rules in CLAUDE.md hold: don't ask questions, decide and write the ruling down; test-first; document
  everything in the project; never merge or push without the owner; commits end with the Co-Authored-By line.
- Never enter the owner's Apple ID password, never accept Apple's agreements, never submit declarations (age rating,
  App Privacy) without the owner's explicit yes: prepare them and ask.

## Tasks
1. **The Mac toolchain** (`docs/IOS-START-HERE.md` §2): Godot 4.7.2 for macOS and its export templates, Xcode with the
   iOS SDK, Homebrew `coreutils` and `flock` (the test scripts use `timeout` and `flock`), Node 24 (server tests). Done
   when `tests/run_tests.sh` passes on the Mac with the same count as on Linux (6016/6018) and
   `npm --prefix server/modules test` passes. Write every Mac difference into DEVELOPMENT.md (a "Mac" section).
2. **Spike: Voxel Tools on a real iPhone.** An "iOS Spike" export preset like "Android Spike" (the spike scene), exported
   to an Xcode project, run on the owner's iPhone. Proves: the GDExtension loads (the dylib is embedded and signed),
   terrain streams and meshes, collisions work, Metal renders both styles. If it does not load: build Voxel Tools for
   iOS from source (Zylann's repo, the 1.7 tag, `scons platform=ios`) or embed it as an xcframework; write down which.
3. **The iOS export preset** ("iOS"): bundle id, the owner's Team ID (from Xcode, the owner signs in), icons from
   `assets/brand/` (all sizes), the launch screen (the teal splash), landscape only, the Mobile renderer, usage texts
   (Photos add-only; notifications if Task 6 is built), export compliance (the game uses only HTTPS: "no non-exempt
   encryption"). Extend `test_release_version.gd` to the iOS keys (short version, build number). A debug build runs
   the whole game on the iPhone: menus, a Survivor world, a Sandbox world, online with an Android emulator or phone.
4. **Safe areas and screen shapes.** The HUD, the step card, the chat and every panel stay inside
   `DisplayServer.get_display_safe_area()` (notch or Dynamic Island, home indicator); the HUD layout tests
   (`test_hud_layout.gd`, today at 2400×1080 and 1334×750) gain an iPhone 19.5:9 size (2556×1179 with its safe area) and
   an iPad 4:3 size (2732×2048), in every button size and hand (M5 T1).
5. **Photos: save and share on iOS.** SAVE into the Photos library (`PhotoFiles` / `photo_mode.gd` today treat
   non-Android as "desktop folder"); SHARE through the iOS share sheet (`photo_share.gd` has only the Android intent).
   A small iOS plugin (Swift, a Godot iOS plugin or a GDExtension) or an existing MIT/CC0 one; the grown-up's
   photo-sharing switch still decides whether SHARE shows (`test_photo_share_switch.gd`).
6. **Farm reminders on iOS** (optional, like Android's `android_farm_notifier.gd`): local notifications through
   `UNUserNotificationCenter`, asked for only when the child sets a farm up, never for under-13 without a grown-up.
7. **Haptics and the development server.** `Feel` buzzes only on Android (`OS.has_feature("android")` in
   `autoloads/feel.gd`): use the mobile feature so iPhones buzz too (`Input.vibrate_handheld`). `OnlineConfig
   .server_for_build` gives Android debug builds 10.0.2.2: an iOS debug build needs the Mac's address on the Wi-Fi (or
   the release server). Test-first in `test_feel_rules.gd` / `test_online_config.gd`.
8. **Performance on iPhone.** The autopilot (the developer menu, debug builds) in every universe, both styles, MEDIUM and
   LOW, on the oldest iPhone the owner can borrow; the weak-device rule for LOW (M5 T3: memory and cores) checked for
   iPhones; the IPA's download size. The bar: §7.
9. **The shop on iOS (only if the owner turns it on):** a StoreKit 2 backend for `Billing` (`core/shop/`), the same
   parent gate, product ids from App Store Connect in `ShopCatalog`; the fake store stays for debug builds.
10. **App Store readiness:** App Store Connect record (the owner creates it: an agreement), App Privacy answers drafted
    from `docs/store/data-safety.md`, the age rating answers from `docs/store/families-and-rating.md`, the Kids category
    decision (owner and lawyer), iPhone 6.9"/6.5" and iPad 13" screenshots (the shot list in `docs/store/screenshots.md`),
    the review notes (how to reach online play: a 13+ profile), the privacy and support URLs (already live on the
    server). New file: `docs/store/app-store.md`.
11. **TestFlight, acceptance and release:** archive in Xcode, upload to App Store Connect (the owner's account), TestFlight
    to the owner's testers, the acceptance run on the iPhone (the tours and checklists of M3–M5, online with an Android
    phone), then submit for review with the owner's yes. Record it like `docs/devlog/2026-09-26-release-1.0.0.md`.

## Review focus (what most likely bites on iPhone)
- The GDExtension on iOS (Task 2) — everything else waits for it.
- Safe areas: a HUD button under the Dynamic Island or the home indicator looks fine in tests and is untouchable on a phone.
- Memory: iOS kills a game that uses too much memory without a crash dialog; watch the voxel streaming at view 128.
- Background and foreground: iOS suspends the game when the child switches apps; saves (`Profile.save`, the world's
  save) and the online link's rejoin (M4 A) must survive it.
- The first launch: Apple reviews the first minute very closely (age screen, no dark patterns, the parent gate).
